# 問題の深さに関する再監査

2026-11-12。PR #2の初版 `4758cfc` に対するユーザーレビューを受けた追加改善。

## 初版の不足

`src/levels.js` と `scripts/validate.js` は標準解への開扉出現を確認していたが、それだけでは全ての解に必要とはいえなかった。

- 005: Aを閉じ続ける問題であり、後でAを開ける問題ではなかった。
- 009: DRUの3手で、回り込みが小さかった。
- 011: 5手・開扉0枚の迂回解があった。
- 012: 標準解はB:Rでも、両方向ドアを使わない7手解が残っていた。
- 018: 二組の競合は成立するが、独立した小さな結び目を順に通る構成。
- 020: 全てのクリア状態で両方向ドアA/Cは閉じており、方向選択を使う最終問題ではなかった。

## 検証方法の強化

- `requiredInEveryWin`: 全出口状態で特定のドアと方向を必須にする。
- `minimumBidirectionalOpens`: 全出口状態における最小の両方向開扉数。標準解だけから計算しない。
- `before`: 全クリア可能状態で順序を検査する。Bより先にAが開いた状態から勝てるなら、その順序は必須と主張しない。
- `minimumSteps`: 意図した回り込みを短い抜け道が壊していないか検査する。

## 現行ルール内で実装した改善

009は11手 `DDDRRRUUULL`。隣に見える出口へ、左辺・下辺・右辺・上辺を回って戻る。標準解は出口からマンハッタン距離5まで離れる。

011は4手 `RRDL`、最小開扉2枚。Aを右へ、Bを左へ押すことを全てのクリア状態で要求。どちらかの必要方向を禁止すると解けなくなる。2枚とも左右の最終辺には床があり、壁で逆向き回転を禁止した見せかけの両方向ドアではない。

## まだ完了と主張しない項目

005の後回し、012の必須の方向選択、018の深い相互依存、020の3要素の統合は継続課題。1辺だけの葉では、方向の選択肢を増やすと迂回可能になり、必須化すると反対側へ到達できなくなるケースが多い。探索の不成功を「数学的に不可能」の証明として扱わない。

一部に長さ2マスの葉を導入する案を提示。90度・一度きり・押すだけは維持できるが、掃引領域とゲームルールが変わるためユーザーに方向性を確認中。現時点では本番エンジンの物理を変更していない。
