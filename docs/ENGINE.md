# 辺、蝶番、90度

## レベル形式

`src/levels.js` が全レベルの正本。実行時に乱数生成しない。座標は右が+x、下が+y。

```js
{
  id: '001', name: 'OPEN',
  cells: [[0,0], [1,0], [0,1], [1,1]],
  walls: [[[0,1],[1,1]]],
  start: [0,0], goal: [1,0],
  doors: [{ id:'A', hinge:[1,1], leaf:[0,-1], push:['R'] }]
}
```

- `cells`: 歩ける単位正方形の左上座標。人物はその中心に立つ。ないマスは固体。
- `walls`: 格子頂点2つで表す長さ1の静的な辺。床と固体の境界は自動的に壁になる。
- `hinge`: 格子頂点。常に固定される回転軸。
- `leaf`: 閉じた葉の単位ベクトル。`[0,-1]`なら、蝶番から上へ1辺を占める。
- `push`: 押す移動方向。`['R']`なら西側の人物が東へ押す一方通行。`['R','L']`なら両側。leafと直交する方向だけ有効。
- その他の文字列は日本語説明・章・検証用proof。UIのルールには影響しない。

## 状態と遷移

状態は `{ p:[x,y], doors:[null|'U'|'R'|'D'|'L', ...] }`。nullは未開扉。開扉後の値が葉の向きになる。

例のAは閉じた状態で `(1,0)—(1,1)` にあり、床 `(0,0)` と `(1,0)` の間を塞ぐ。西からRで押すと `(1,1)—(2,1)` に回る。上右 `(1,0)` と下右 `(1,1)` の間が新しい壁になる。人物は回転完了後に上右へ進む。

同じAが両方向なら、東側からLで押した最終辺は `(1,1)—(0,1)`。葉の元の向きと移動方向の外積の符号で時計回り／反時計回りが決まる。どちらも同じ蝶番、同じ長さ、正確に90度。

`transition(level,state,action)` が唯一の移動・開扉規則。入力を変更せず、成功なら新しい状態、拒否なら元の状態と理由を返す。UI、BFS、検証、テストの全てがこれを呼ぶ。再開扉、引く操作、斜め移動はない。UNDOは直前の不変状態、RESETは初期状態に戻す。壁への入力は履歴に入らない。出口に着いた状態は終端。

## 衝突と掃引領域

葉は厚みゼロの長さ1、人物はマス中心を移動する抽象モデル。描画の厚みは装飾で判定には使わない。

1. 移動先が床で、横切る辺に静的な壁がないこと。
2. 横切る葉が開いた葉なら拒否。閉じていても禁止側なら拒否。
3. 開いた先の辺が静的な壁、固体との境界、他の閉じた葉／開いた葉と重なる場合は拒否。
4. 回転時の扇形は移動先の1マスの中に収まる。このモデルの全障害物は単位格子辺か固体マスなので、内部を横断する障害物は存在しない。扇形の始端・終端で上の判定を行えば、内部の壁/葉を見落とさない。単に蝶番や葉先の端点を共有するだけなら許可。
5. 人物は回転中に元のマスで待機し、その後で移動する。人物と葉が掃引中に交差する見せ方を避ける。

箱、他の人物、任意角度の障害物、長さ2以上の葉を追加する場合、この掃引領域の前提は成り立たない。現在はそれらをサポートしない。

## 探索と可解性

BFSは人物座標＋全ドアの向きをキーにして、全到達状態を列挙する。打ち切りや確率的判定はない。最初の出口が最短手数。全出口状態の開扉数の最小値が最小開扉数。出口から逆向きにたどった集合で、各状態からまだクリアできるかを判定する。

UIはこの集合を用い、詰んだ直後にUNDOを案内する。「ヒント」は今の状態からの次の1歩だけを出す。8面最大444状態なので、Workerやネットワークは不要。

アニメーションは確定状態の表示。扉を開く入力の後350msは次の移動を受け付けず、UNDO/RESET/画面変更は直ちにアニメーションごと置換する。遅延コールバックが過去の状態を書き戻すことはない。
