# 既存プロトタイプの監査

対象: main の `9b36146194c97285e6fc8a19fa67e2d6bf9d2adc`、旧 `index.html` の STAGES / tryMove / solver。2026-11-12。

## 再現した問題

旧遷移規則を独立した探索用スクリプトで再現し、実際に最短手順を取得した。U/R/D/Lは上下左右。

| 面 | 旧最短手順 | 開扉数 | 問題 |
|---|---|---:|---|
| 001 | RRDDDD | 1 | 基本の開扉は通るが、物理はマス移動 |
| 003 | DDDDRRR | 0 | ドアに触れずクリア。「新しい壁」を学ばない |
| 005 | RRRR | 1 | 正面Aを開けて直進クリア。「今は開けない」が成立しない |
| 009 | URRUUULL | 1 | 3枚あるがAだけでクリア |
| 011 | UUUU | 1 | 正面から一直線 |
| 012 | UUUU | 1 | 二方向の選択をしなくても一直線 |
| 018 | UUUU | 1 | A/Bを無視しCだけでクリア。干渉を使わない |
| 020 | UUUU | 1 | Cだけでクリア。他の4枚が不要 |

- `door.p` が1マスを占有し、開いたら任意の `to` に移動する。蝶番座標も共有する端点もない。001のAも003のAも90度の辺回転ではない。
- 005 Bの `to=[2,3]`、020 Cの `to=[2,3]` は `#` の壁マス。旧コードは blocked により拒否するため、その操作は定義されていても実行不能。「物理的に正しいドアがある」という検証ではない。
- UIとsolverに同じ処理を二重記述し、solverはグローバルstate/history/wonを変更する。
- 初期HTMLにタイトル画面・解放管理・保存・音・減らす動きの設定がない。起動時の可解判定しかなく、概念や失敗例を検査していない。

## 仕様上の解釈と残した範囲

- 005の受入条件「早い開扉が罠」を満たす。Aを後で必ず開ける課題ではなく、最後まで閉じる課題として明記した。
- 012はBの方向だけで一律に勝敗が決まる課題ではない。先に開けたA/Dとの組み合わせを選ぶ。機械可読レポートにBの両方向の成功/失敗継続を記載する。
- 018の干渉は、相方を開くと必要なドアが開かなくなる競合。相方を開いて回転先を空ける課題と偽ってはいない。
- 20問は品質条件付き。優先8問を収録し、残り12問は未収録とした。
- 人間の楽しさ・手触り評価、実物のiPhone/Androidでの入力と音の試聴は自動検証の範囲外。
